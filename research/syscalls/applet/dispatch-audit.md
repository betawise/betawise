# ROM dispatch and shipped applet message pumps

## Scope and evidence

This is a static audit of the **three SHA-256-inventoried ROMs** (AS3000 3.01,
Neo 3.01, Neo 3.21) and **all 56 unique original applet images** in the maintained
vendor inventory. A hash census of every `.OS3KApp` under `Ghidra/` found no
additional original applet image outside that inventory. Betawise applets are
source consumers, not evidence of manufacturer contracts.

The full census is generated by [trace-messages.py](trace-messages.py). The
checked-in [dispatch-summary.json](dispatch-summary.json) records every input,
header entry offset, evidence hash, resolved-function count and unresolved
Ghidra table count. Raw disassemblies, all 56 entry/dispatcher transcripts,
full candidate lists, Ghidra logs and projects are preserved locally under
`.research-work/message-dispatch/`; the clean reproduction and its candidate
census (`dispatch-inventory.json`) are in `reproduction-v2/`, with completed
applet graph walks in `reproduction-v2/pumps/`. Earlier investigation output
is retained in `complete/` and the separately named ROM transcripts.
They visited 3,825 function entries (including terminal syscall stubs), with
no queued resolved calls remaining. That count is **not** a claim that every
indirect function pointer has been resolved.

The scanner retains every register-indirect `JSR` candidate, every detected
read/add of header field `+84`, references to reviewed cached callback globals,
and message-shaped immediates. It does not treat arbitrary immediates as
messages. Resources can decode as instructions in a flat binary; function
prologue hints are not authoritative boundaries. Static switch recovery follows
the vendor compiler's bounded dense/sparse PC-relative tables and records the
added targets. Ghidra still reports some unrecovered tables; those warnings
are retained, and physical effects are not inferred from decompiled C alone.
No hardware, saved session or display was modified. No screenshot inference
was used. Parameter/reply branches were checked against original instructions.

## Routing rules that apply before decoding parameters

Message bits `16..23` select a transport family in many applets; bits `24..31`
select a synthetic/provider request in others. There is **no universal rule**
that discards all upper bits. Some handlers compare the whole message, some
compare a low byte and then full-code exceptions, and some reject synthetic
messages entirely. The same low selector can have unrelated meanings in a
font, dictionary, calculator, spelling or CoWriter provider.

The physical family mapping is independently visible in MathFacts RP's
entry switch at `140–1B4`: `SWAP(message-10001)`, a seven-entry table at `15C`,
and PC-relative string loads. Its exact table maps `10001` to “Connected to ADB.”,
`20001` to PS2, `30001` to USB keyboard mode, `40001` to USB direct, `60001`
to a printer and `70001` to IR; `50001` takes the default arm. ROM string `BC`
(Neo 3.21 `446D28`) identifies the separate `500xx` pump as AlphaHub.
This prevents accidentally swapping ADB and PS/2, or calling `500xx` USB.

`AppletSendMessage` (Neo `439C60`, AS `4E0F02`, Neo 3.01 `5E385E`) installs the
target A5 context and adds bit 24 after retaining the low 24 bits, **except
exact codes `1C/1D`**. Native foreground, printing and transport pumps invoke
cached applet callbacks directly without applying that synthetic bit. Timer,
UART, IrDA service and wireless callbacks with different argument lists are
not automatically `ProcessMessage` dispatches.

## Additional ordinary messages and reply contracts

| Message | Producer and parameter | Consumers / reply |
|---|---|---|
| `00`, idle | Ordinary foreground idle, usually parameter zero. Neo battery diagnostic `42784E–42785A` calls the diagnostic applet with **`FEDCBA98`** instead. AS and Neo 3.01 equivalents also contain this sentinel. | Avoid promising param is universally zero. Foreground idle reply 7 requests a refresh. |
| `0E`, print setup failed | Neo `416208–416212`; AS print entry `4C5D0C`. A printer-driver opener failed, so the foreground callback receives `(0E,0,status)`. | KeyWords clears its busy/menu flag. Inspiration takes its redisplay path. This is not a general applet shutdown message. |
| `18/19/1A` | Boot/registration, foreground selection and focus switch/teardown. `18` and kill-focus use zero at the reviewed sites. `19` retains the entry-offset/launch value in the foreground loop. | Preserve the existing opaque focus parameter contract. Focus loss does not establish cancellation of all asynchronous callbacks. |
| `1B` | Existing [refresh investigation](messages.md): zero, `FC` font reload, `FE` cursor-style refresh. | Full-code matching in native editor/form handlers. Font selection can emit `FC` even without a changed face. |
| `1C/1D` | Settings/resource read/write; direct updater and applet-specific setting queries. | Twelve-byte native record below. Some settings-write handlers fall through their ID-reply path; do not assume a universal zero reply. |
| `24` | No verified producer in the inventoried ROM dispatch traces. | Inspiration treats it like `1B/25` and redraws. `MSG_REFRESH_LEGACY` names that consumer behavior, not a recovered system event cause. |
| `25`, low-battery warning finished | Foreground `417C82–417C8C` calls `426DF2`. That calls `427458`, which checks battery discharge >97, displays string `2E` (“Low Battery.”), waits for acknowledgement, and returns true. The loop then selects `25`. | Inspiration redraws. The loop does not construct a new payload for this event: `param` is not a battery measurement or pointer. |
| `26`, get ID | Neo RAM-applet registration `418A7E–418A8E` initializes status to `FFFE`, invokes `(26,0,&status)`, and uses its low 16 bits to find/update the installed slot. AS `4C89EE`, Neo 3.01 `5C8254` do likewise. | SpellCheck returns `A005`, Inspiration `A100`, MathFacts Offline `A02A`; these are IDs, not table indices or pointers. Header spelling ID remains the metadata source. |

The ordinary foreground loop's **reply** 7 has different meanings by phase:
non-idle handling switches back/selects another applet; idle handling schedules
`1B/0`. Replies `0A/0B` initiate print/IR-related firmware flows followed by
refresh. These values are replies, not additional message IDs. Transport pumps
have their own reply switches and do not share that entire policy.

### Settings request layout

The record at `param` for `1C/1D` has these target offsets (68000, big-endian,
two-byte structure alignment):

| Offset | Field | Evidence |
|---|---|---|
| `00` | 16-bit flags | Read handlers test low-byte bits 0, 1, 3 and, in some providers, 5. |
| `02` | 16-bit resource type | Native query constructs `0103`. |
| `04` | 16-bit resource ID | Native cursor-style query uses `100F`. |
| `06` | 16-bit byte length | Read result / write input; zero in pointer-return queries. |
| `08` | 32-bit borrowed data pointer | Read/write data, not a second status pointer. |

`41C304–41C34C` constructs flags `0029`, type `0103`, ID `100F`, length zero,
data NULL, and dispatches `1C`. `41C394–41C3FE` writes the same setting via `1D`
with length 6 and words `1001/1002`. The reader returns the native cursor-style
boolean by testing the first word for `1001`. This evidence establishes the
setting, not an independent general “insert/overwrite” enum.

Flag bit 3 resets a provider's retained resource cursor; bit 1 affects traversal
of resource types `1..FF`. Bit 0 selects provider-managed copy/synthesis behavior
in the reviewed stock handlers (including provider scratch-buffer limits).
Exact flag support is provider-specific; a universal flags enum or allocator
contract would be misleading. `AppletResource_t` is only the six-byte on-flash
record header and must not be cast to this twelve-byte callback request.

## Transport pumps and payloads

All seven families use the same observed **five 32-bit fields** when a request
is supplied: input length, input pointer, output capacity, output length, output
pointer at offsets `00/04/08/0C/10`.
Some close/wait events pass **NULL instead of a request**. Consumers must branch
on message before dereferencing. All pointers/records are borrowed synchronously.

| Family | Pump / dispatcher roots | Observed message suffixes and parameter details |
|---|---|---|
| `100xx`, ADB | AS `4D3722` pump; `4D3DFC` router; applet callback cached at `4468`, selected protocol callback `4464` | `01` open, `02` host input, `03/04` control, `06` raw output poll, `07/08` text poll/drained, `0C` close, `16/17` control, `1E/1F` native key down/up, `11E/11F` queued-output variants. Native key input is two bytes. Some control/input events intentionally route to the ROM/protocol handler, not the ordinary foreground applet. Detailed `03/04/16/17` meanings remain unnamed. |
| `200xx`, PS/2 | AS `4D255E` pump, `4D2DE6` router, `4D2A6C` host-byte receiver; cached applet `4428`, protocol `4424` | `01`, `02`, `06`, `07/08`, `0C`, `14/15`, `1E/1F`. Wrapper initially supplies capacity `400`. `02/06/14/15` route to the selected protocol callback; other cases normally reach the applet. AS `4D2770–4D27AA` selects `2011E/2011F` when output is queued, otherwise `2001E/2001F`. These busy variants are also recognized by AlphaWord/Inspiration; the router still initially supplies capacity `400`, so USB busy-capacity rules must not be copied to PS/2. |
| `300xx`, USB keyboard | Neo `41CA36`; corresponding roots AS `4CC4BE`, Neo 3.01 `5CC0E2` | Existing `01`, `07/08`, `0C`, `12/13`, `1E/1F`, `11E/11F`, `21E/21F`. Keyboard output and key events have distinct reply policies from direct USB. |
| `400xx`, USB direct | Neo `440D7E` bulk loop / `441064` default router; `43F97A` applet selection | Existing `01/02/06/0C/12/13`. Direct bytes, not HID packets. Endpoint transport and callback selection are separate layers. |
| `500xx`, AlphaHub | Neo `4199C0` pump, `419FF2` default router, cached callback `3EB4`; selects applet ID `A001` | `01` empty open; `02/05` received input; `06` empty queue poll, **capacity `3FC` and output at `35FC`**; `09/0A` empty control notifications; `0C` close. Reply 4 queues output. Reply 8 releases a selected handler. Cause of control event `09`, and exact wire distinction between `02/05`, remain partly unresolved. |
| `600xx`, print | Neo `416156`, `416302`, `416DBE`, `416F72`, `43D218`, `43D51E`, `43DB1C`, `43DBE8` | `01` open with printer-name bytes; `0D` obtain next text chunk, capacity up to `400`, reply 4 consumes produced bytes; `10` wait/progress, param NULL, reply 8 cancels; `11` wait ended, param NULL; `20` native key request (two-byte native key, zero output capacity), reply 8 cancels; `0C` close commonly has NULL param. |
| `700xx`, IrDA application transfer | Neo `43CD9E`, `43CEA0`, `43D51E`, `43D6E6`; cached selected callback `1193E` | `01` open, `02` received application bytes, `06` output poll, `0C` close with NULL param, `20` native key. Default Escape handler returns `10` and outer key pump returns error `FFFFFAEB`. This differs from print reply 8 / error `FFFFFBB2`. |

The older AS printer writer `4C67CA` raises `60010` when a partial serial write
needs continuation and `60011` when done. Neo writer `416DBE` raises `60010`
once when an ongoing write exceeds 500 uptime ticks; it polls cancellation and
emits `60011` only after that wait notification. These are progress transitions,
not more chunks. `6000D` is the chunk-producing request.

The native editor transfer state machine (`4285CE`) compares both the low byte
and full codes: `60001` copies a maximum 39-byte printer name and enters phase
6; `6000D` starts scanning; `6000C` uses phase 10; `60020` Escape uses phase 8.
Form transfer has corresponding scoped cases at `42F744`. AlphaQuiz has its
own implementations (`762A` print, `71DC` direct, `730A` Hub); KeyWords and
Inspiration have their own transport pumps. Shared suffixes are not sufficient
to infer shared reply/state behavior.

### Selection and restoration of transport callbacks

`43F97A` finds an applet by header ID, changes identity/A5, and first invokes
its transport-open callback with a native empty request and capacity `400`.
Replies `11/12` accept the selection. It then forwards the triggering message.
For PS/2 open it can additionally forward `20002`; this is a distinct path,
not a universal open payload. `43FBC6` restores a previous/default callback.
The Hub, USB-direct and IrDA default routers use these helpers. Consequently
finding a callback pump does not mean the foreground applet receives every
packet or control event.

## Provider-specific request families

| Provider | Delivered selectors / payload and reply |
|---|---|
| Stock Neo fonts, including the 5 stock sizes and 11 alternate fonts | High byte present, low selector 1 returns name pointer through param; 2 returns normal descriptor; 3/4/5 optional face pointers (unsupported stock faces return NULL); **6 returns pixel height as a zero-extended 32-bit scalar through param**. Native font getter uses 2–5 with normal/normal/bold fallback for absent faces. No descriptor pointer is returned by query 6. |
| `CW_Topics`, `CW_MainDictionary` | Synthetic selector 1 returns data pointer `image+106` through param. The **status pointer must have 8 writable bytes**: writes zero at `+0`, data pointer at `+4`. A normal four-byte status word is insufficient. |
| CoWriter | Full codes `01000000..01000005`. Request 3 takes a native key word, not a font output-pointer address. The result at the status argument is **10 bytes**: state byte `+0`, action byte `+1`, 32-bit count `+2`, pointer `+6`. Requests 0/1 set up state/buffers, 2/4 change/reset state, 5 marks a transition; exact product-level naming remains provisional. No generic `uint32_t status` call is safe for these requests. |
| SWFont / StyleWriterFont | Exact code `01A01000`, low byte of param indexes a 256-entry relative-offset table; a code-relative base is added and the selected borrowed ROM address is written to status. Record contents require separate printer-format research. |
| SpellCheck USA/Spanish | Synthetic low selectors **1–7** are unpacked into an applet-native seven-argument handler from the five-field request. Inputs/outputs are operation-specific. The selector table is at USA `360E`; this audit records it without inventing names for every dictionary operation. |
| Thesaurus Small/Large/Spanish-to-English | Synthetic low selectors 0–6, dispatcher `45C`, are a separate service API. Selectors unpack packed byte/word/pointer records into different internal routines; status carries byte/short/bool results. They are not font queries despite overlapping values. |
| Calculator | Synthetic selectors 1/2 use the five-field native request. At most `18A` input bytes are copied and NUL-terminated. Selector 1 needs at least one output byte and produces a one-byte result; selector 2 needs at least four output bytes and writes a result pointer/count of four. It is a calculation service API, not a font or transfer-open callback. |
| Beamer | Strips the synthetic high byte and dispatches selectors 0–3 to its own service (`3FE`). Parameters include a packed pointer record for selector 0 and scalar/word inputs for other selectors. This is not an ordinary message family. |

For font selector 6, the direct evidence is the implementation in all 21
inventoried stock/alternate Neo font images: initialize, load the descriptor's
height byte, zero-extend it, and store a long through `param`. This establishes
the provider contract. A ROM caller that consumes selector 6 has **not** been
identified; the reviewed native font getter calls selectors 2–5. Calling this
a separately verified ROM consumption contract would overstate the evidence.

Thesaurus does return ordinary four-byte replies. At dispatcher `45C`, selectors
0, 1, 3, 5 and 6 zero-extend an internal byte result into `*status`; selector 2
sign-extends a 16-bit result; selector 4 sign-extends an 8-bit result. The byte
results for selectors 0/1/3/5/6 report completion or success; the count and word
class selectors have separate scalar meanings. Invalid selectors write zero.
These are synchronous service replies, separate from the CW dictionary applets'
eight-byte result record. The decoded operations are group lookup, enumeration,
group count, headword copy, word class, related-word copy and linked-antonym lookup.
Their exact request layouts, truncation rules and native qualification are in
[dictionary service research](../../dictionaries/README.md).

The complete per-image pump evidence includes Control Panel 1.1/1.7,
AlphaWord Plus old/new, AlphaQuiz, both KeyWords versions, KeyWords Wireless,
Inspiration, Beamer old/new, all spell/thesaurus variants, Calculator old/new,
MathFacts RP/offline, Responder, Accelerated Reader, Wireless File Transfer,
Wireless Updater, Text2Speech Updater, CoWriter and its two data applets,
StyleWriterFont and all font images. Wireless product entry points often
recognize transport-open selectors solely to update connection UI; those
branches do not establish new radio packet protocols.

## Reproduction and limits

```sh
# Complete image/dispatch candidate census; hashes checked, no emulation.
python3 betawise/research/syscalls/applet/trace-messages.py /tmp/message-census

# Fresh Ghidra imports, bounded compiler-table recovery and resolved-call walks.
python3 betawise/research/syscalls/applet/trace-messages.py /tmp/message-ghidra --ghidra

# Check scalar-vs-pointer instructions and exact family/warning strings.
python3 betawise/research/syscalls/applet/check-message-facts.py

# Execute production terminal font callbacks; no LCD or saved guest state.
python3 betawise/research/syscalls/applet/check-font-messages.py /tmp/message-fonts
```

The font check exercises query 6 first, checks its scalar height with adjacent
canaries, sends `MSG_INIT` as required by the current BetaWiseTerminal lifecycle,
then checks the normal descriptor and optional faces for
8-, 7- and 6-pixel production fonts. It caught the distinction between a
pointer-shaped result and the expected scalar. This qualifies those callbacks,
not physical font selection or the entire screen refresh pipeline.

The full Ghidra run uses fresh project files only. Its direct/adjacent-immediate
call walks terminate with pending zero, but register-loaded callbacks and
unresolved computed tables remain explicit limitations. The inventory's raw
JSR candidates include unrelated sort/format/UART/syscall callbacks and resource
false positives. It would be incorrect to report those as applet messages or
claim every possible dynamic dispatch target was proven. Unknown `24` producer,
ADB control subevents, PS/2 `14/15`, Hub `09/0A`, and several provider operation
semantics remain documented as open questions. No expected screen fixture was
created or regenerated from this investigation.

Detailed dictionary, Thesaurus, and SpellCheck request layouts and native qualification
are in [dictionary service research](../../dictionaries/README.md), including the
correction of SpellCheck's selector range and Thesaurus antonym lookup.
