# Native Neo 3.21 font dialog reference captures

## Status: INCOMPLETE — unverified reference captures

The user reported on 2026-11-23 that the associated interactive demo still does
not work correctly. These captures preserve observations from incomplete
research; they are not verified examples or acceptance-test expectations.
Stable samples and recorded hashes do not establish correct dialog behavior.
See the [research status](../README.md).

Sixteen supported templates, rendered by original firmware in local MAME.
`font-dialogs.png` is the labeled contact sheet. `layout-N.mame.png` is the
emulator screenshot; `layout-N.png` is a lossless native 264x64 reconstruction
of its LCD controller RAM. The contact sheet enlarges those pixels 3x using
nearest-neighbor scaling. No model vision was used.

Each layout receives representative title, right-title, body and protected
input strings in all regions. The normal key handler receives `A` for each
region. Template defaults control which fields are displayed. These examples
are illustrative, not exhaustive widget or navigation coverage.

The Lua capture script calls the original firmware entry points, records
region flags, input renderer kinds and cursor coordinates before hiding the
console cursor through slot 6, checks completion and mode, records three
identical controller RAM/flag samples through NeoLCD.lua, then restores and
checks the original cursor mode. Firmware calls use bounded completion
predicates. Tests run against disposable emulator NVRAM under
`.research-work/dialog-font-reference` (initial capture used
`.research-work/dialog-gallery`). No saved user session is loaded.

`mame.log`, `layout-N.geometry.txt`, `layout-N.lcd.json` and `manifest.json`
preserve the capture evidence. Hashes and sample stability establish capture
provenance, not expected rendering correctness. There is no verified glyph
profile for this firmware font here; these images are references for human
review and are not acceptance-test expectations or decoded-text assertions.

The standalone `gallery.lua` currently uses absolute workspace paths.
`render-gallery.py` regenerates presentation images from the preserved records.

Only the overview contact sheets are retained as notable illustrative output.
Per-layout captures, geometry dumps, RAM records and logs are regenerated by
the gallery source; they are not accepted behavior references.
