# Bible compression findings and regeneration

The local experiment tree held about 6.1 GiB. Redundant source copies,
disposable flash/RAM, compiler AST/preprocessor intermediates and old binaries
were retired. This report retains summaries, source builders, source identities
and compact result tables, rather than the deleted-file inventory or raw logs.

| --- | --- | --- |

| Context/arithmetic models | [Context models](../context-models.md), context-results.json | context_models.py, test_context.py |

Additional compact findings are in additional-findings/. Topic reports retain
historical scope, timing and caveats, including the private viewport selection
regression. Historical result paths/hashes identify observations; they do not
require those generated directories to remain available.

The baseline KJV source URL/revision/hash are in [source.json](../source.json).
Formatted-source inputs use the BibleWise upstream data submodule pinned at
`93ff30bbb530c53cd2ab26e42ee555d3938ded14`. Supply those source inputs, the
SDK, m68k-linux-gnu GCC/binutils, Clang for maintenance metrics and the reviewed
private ROMs/emulator for device tests. Modern-edition text remains external.

From the workspace root, restore the frozen source with prototype_support.py
as documented in [prototype reproduction](../prototype/REPRODUCE.md). Use fresh
outputs and omit PREBUILT_DATA when rebuilding missing caches; build_data.py
regenerates normalized source, codec, index, pruning and verse resources from
the pinned upstream. Navigation.h is generated by prepare.py. No normalized
input copied into an old run is required.

```sh
python3 betawise/research/bible-reader/measure.py \
  .research-work/bible-compression/kjv.json --output /tmp/bible-baseline-new
python3 betawise/research/bible-reader/prototype_support.py
python3 betawise/research/bible-reader/measure-reader-builds.py \
  --output /tmp/bible-reader-costs-new
```

The measurement runner rebuilds app/ELF files, link maps, preprocessed C,
Clang ASTs, stack records and metrics. For just a newly generated preprocessed
folder, run reader-maintenance.py FOLDER. Device runners create disposable
flash/RAM and new screen/state records; apply all current deterministic local
LCD/cursor/bitmap rules before accepting historical harness reruns. Raw outputs
are useful during active validation, but are not preserved in this commit.
